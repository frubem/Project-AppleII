ROMX - Mythbuster #4 :  "Lower case on Apple II and II Plus"
MYTH 1: There are no modern solutions to display lower case on pre-Rev7 motherboards.
MYTH 2: The original ROMX board only works with Rev7 and later.
MYTH 3: The ROMX 2513 Special Video ROM Set does not include lower case.
First, some background. While all IIe's and later support upper and lower case text, that was not always the case (pun intended). The early Apple II's could only enter and display upper case letters. Of course, when people starting using their Apple's to do things like word processing this issue had to be addressed.
Lower case capability requires three distinct functions: display, keyboard entry, and software support. 
DISPLAY : Early Apple's used two different circuits to produce a TEXT display. Pre-Rev7 motherboards had a 2513 Character ROM chip that only produced upper case characters. Since that requires 6 data bits to display the full set of alphanumeric characters plus some extra symbols, the remaining 2 bits of each character byte in memory were used to create inverse and flashing text. In Rev7 and later boards, the 2513 was replaced with an EPROM-compatible 2316B ROM and all of the data bits were connected it. The stock chip still only produced upper case text, but with a simple EPROM swap you could add whatever character set you wanted including lower case.
For pre-Rev7, the ability to display lower case was first addressed with special character ROM boards like the Dan Paymar Lower Case Adapter. This used a small jumper socket to pick up the extra data line needed to switch between two ROM chips. One produced upper case and the other lower case. Another popular way to display lower case was by using an 80-column card which would have its own character generator that included lower case. Using any of these methods would get you lower case display, but that's only one-third of the problem.
KEYBOARD ENTRY : Although every Apple keyboard has had a shift key, on the II and II Plus this only worked to type special characters. All alphabetic letters were upper case only. This presented a dilemma for software authors who wanted to support lower case. One solution was to use special key sequences using the esc key or control characters to alternate between upper and lower case. This had the advantage of not requiring any hardware changes but was quite cumbersome to learn and use in practice. There were also third party products such as the Videx Enhancer ][ that replaced the keyboard encoder to provide lower case as well as other features.
I'm not sure who first came up with the idea to run a wire from the shift key to the Game I/O connector, but this took advantage of the rarely used PB2 input and allowed the state of the shift key to be read by accessing (PEEKing) address $C063. With the Apple II Plus, a new keyboard design was used which already had the ability to generate lower case. But it needed a small modification and switch to enable it. For a complete discussion of these modifications, check out Jim Sather's "Understanding the Apple II," pages 7-36 through 7-38. Despite requiring software support for the one-wire shift key modification, it was adopted by most 80-col boards and soon became the de facto standard for allowing full use of the shift key on Apple keyboards. 
SOFTWARE SUPPORT : Finally, even after providing lower case display and keyboard entry, software must be written to support it. As previously mentioned, the shift key mod needs software specifically written to test PB2 for every keystroke. The standard F8 monitor ROM routine for reading the keyboard (GETLN) also needs a small tweak. Fortunately, this only requires one byte at location $FD83 to be changed from $DF to $FF to prevent it from automatically upper casing all input. Other programs just bypassed this routine and wrote their own keyboard entry code to handle lower case.
ROMX SUPPORT :  ROMX has always supported a Text ROM board that can add 15 additional fonts to the standard Apple character set. Note that there are two versions of the Text ROM: one for pre-Rev7 machines and the other for later versions. What may not have been as obvious though is that these boards also give you lower case support for the 40-column screen. Any programs designed to work with a lower case adapater (e.g. Dan Paymar) will automatically be compatible with the ROMX Text ROMs. Of course, you can select between a CAPS ONLY font versus many Lower Case fonts using the ROMX menu system. And you can also associate a given font with any given System ROM image. That's important because programs designed for lower case can be unreadable without a lower case display and vice versa. 
And the APPLESOFT BASIC LOWER CASE image normally stored in ROMX Bank 2 makes minor changes to the standard System firmware to allow lower case along with a couple of other changes:.
D970 - 85 -> 86                                         Bug fix for FOR/NEXT loops
FB0A - D0 D0 CC C5 -> F0 F0 EC E5      APPLE title string changed to Apple
FD83 - DF -> FF                                       GETLN routine mod to allow lower case
